§1 · Nguyên lý rút ra

Một mũi tên xuyên suốt 8 mốc

  • wrapper/moat — fork VS Code để mượn ngay distribution và hệ sinh thái extension. Không đấu ở chỗ mình yếu.
  • định nghĩa "tốt" — liên tục tự nâng chuẩn: gợi ý tốt = đoán trước cả một sửa đổi → sửa nhiều file → tự thực thi.
  • vòng lặp học + x10 — agent khép vòng làm-kiểm-sửa, nhắm bước nhảy chứ không cải thiện tuyến tính.
  • Vertical AI — tự huấn luyện model Composer theo chiều dọc nghề code, kiểm soát cả chất lượng lẫn chi phí.
Điểm đắt nhất — mốc 1 và mốc 7 là một cặp đối xứng. Mốc 1 dựng lực Habit (fork VS Code để mượn thói quen sẵn có). Mốc 7 tự tay gỡ chính lực đó (hạ IDE xuống một pane). Cursor không trung thành với hình hài sản phẩm — chỉ trung thành với định nghĩa "tốt" tại thời điểm đó, và sẵn sàng phá thứ mình từng dựng khi định nghĩa ấy đổi.

Tệp user & JTBD

Early adopters (2023–24)

Ai: indie hacker, senior engineer, power user MIT/HN. Đã dùng VS Code, tự trả $20/tháng, 1 dev 1 repo, thích thử tool mới.

JTBD: "Giúp tôi viết code nhanh hơn trong codebase lớn, autocomplete đa file chính xác, đỡ gõ boilerplate."

Cách cũ: Copilot + extension VS Code, copy-paste qua ChatGPT ở tab riêng.

Tệp hiện tại (2025–26)

Ai: team enterprise Fortune 500 (Nvidia, Uber, Adobe), Eng Manager, Platform/DevOps. 10–100 dev, 30% PR do agent tạo.

JTBD: "Giúp đội tôi quản lý một đàn agent chạy song song, tự review PR, và giữ quyền kiểm soát logic dù code do AI viết."

Cách cũ: vẫn Copilot + review PR thủ công; thử Devin/Windsurf nhưng thiếu parallel worktrees.

Cột mốc gây dịch chuyển: v1.0 (Bugbot + Background Agent cho mọi user) là điểm bẻ — biến Cursor từ tool cá nhân thành workflow của đội. Cursor 2.0 và 3.0 đẩy tiếp: khi agent chiếm phần lớn usage, người mua dịch từ lập trình viên sang Eng Manager và CTO.

§2 · Switching cost

4 Forces — và lực nào thật sự giữ chân?

Push — đẩy khỏi hiện trạngCopilot chậm, thiếu ngữ cảnh repo lớn; review PR thủ công quá tải; agent rời rạc không có harness.
Pull — kéo sang CursorTab phản hồi <300ms, Composer <30s/lượt, agent song song trên worktree, Bugbot sửa lỗi một click.
Anxiety — lo ngạiHoá đơn usage khó đoán sau vụ pricing; sợ lock-in vào model riêng; lo privacy vì Background Agent cần tắt privacy mode.
Habit — quán tính giữ lạiPhím tắt VS Code quen tay, team đã set rules, Memories và codebase index đã "học" xong — bỏ đi là mất ngữ cảnh.
Trả lời phản biện — nếu lực mạnh nhất biến mất thì sao? Habit là lực mạnh nhất, nhưng nhóm tìm được bằng chứng nó mỏng hơn tưởng: ngay trong thread pricing, một người viết "I've deleted all these wrappers after discovering Claude Code" — rời đi lập tức khi có biến. Và chính Cursor tự tay gỡ lực này ở mốc 7. Kết luận: moat thật không nằm ở thói quen, nên Cursor phải đi tìm moat mới ở tầng hạ tầng (mốc 8).

§3 · CP3

Ba dự đoán (6–12 tháng tới)

1. Origin GA kèm CI/Merge Queue tự động mở rộng tính năng
Dự đoán: Cursor đưa Origin ra bản chính thức mùa thu 2026, kèm agent tự sửa CI fail và giải quyết merge conflict. · Lập luận: §1 mốc 8 đã công bố Origin xử lý conflict ở quy mô agent; mốc 6 đã có browser để agent tự test. §2 cho thấy tệp hiện tại là enterprise chạy nhiều agent — cần hạ tầng, không chỉ editor.
2. Nhắm Platform team và người không viết code mở rộng segment
Dự đoán: đẩy gói cho Platform/DevOps và PM qua SDK + bản mobile, cho phép mô tả logic bằng ngôn ngữ tự nhiên mà không cần mở IDE. · Lập luận: §1 mốc 7 đã hạ IDE xuống một pane; §2 cho thấy người mua đã dịch từ lập trình viên sang Eng Manager — bước tiếp là người định nghĩa sản phẩm nhưng không gõ code.
3. Pricing lai theo compute, chống Big Tech phát miễn phí mô hình kiếm tiền + Big Tech
Dự đoán: chuyển sang hybrid usage-based (token/compute cho Composer + lưu trữ Origin) kèm gói enterprise. · Lập luận: §1 mốc 6 tự train model rất tốn compute và mốc 8 đổi cả công ty lấy quyền dùng cụm GPU — buộc phải thu theo compute. Khi Claude Code và Codex tích hợp miễn phí, Cursor giữ chân bằng Origin thay vì đấu giá theo seat (§2).

Tự tin nhất — dự đoán 1 (có waitlist, có keynote, có tuyển người làm hạ tầng Git). Gãy nếu: GitHub ra merge queue cho agent trước, và doanh nghiệp không dám rời GitHub vì lý do tuân thủ — khi đó Origin chỉ còn là tính năng phụ.
